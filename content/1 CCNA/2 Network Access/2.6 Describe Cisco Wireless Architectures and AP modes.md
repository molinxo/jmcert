Arquiteturas Wireless Cisco e modos AP conectam uma rede wireless á uma rede cabeada para transferir dados de forma segura. São classificadas em três categorias

- Arquitetura de AP autonoma
- Arquitetura de AP baseada em Cloud
- Arquitetura de AP split MAC

### Autonomous AP architecture

Resumo Three-Layer Architecture

Basic service sets ou BSSs são oferecidos na arquitetura de AP autônoma no Tier 3 de acesso (Switches de acesso/AP's) de uma Arquitetura Tier 3. AP's autônomas conectam SSID da rede wireless com VLAN's da rede cabeada.

O método mais fácil e rápido de transferência de dados via redes wireless e redes cabeadas é encontrado nessa arquitetura. O access point funciona como ponte entre as redes wireless e cabeada. 

O aparelho conectado na rede wireless das AP's consegue enviar dados para outros aparelhos conectados sem usar a rede cabeada.

A Porta Trunk conecta o Switch Core ao Switch de acesso para transportar dados entre VLAN's.

Para cada AP autônoma é alocado um endereço IP fixo para gerenciamento e configuração. Os primeiros parâmetros que devem ser configurados são SSIDs, VLAN's, Canal e Transmission Power.

Cada AP deve se comunicar entre si para troca de dados e funcionamento das VLAN's.
Todas as VLAN's e SSID das AP's devem se extender ao Tier 2 (Distribuição) para que as VLAN's se comuniquem com a rede cabeada.

### Cloud-based AP architecture

Arquitetura baseada em Cloud refere-se a redes wireless e AP's que possuem uma interface de controle com deploy na internet para que todos os devices de redes possam ser configurados, monitorados e controlados por essa interface de forma centralizado.

Lembre-se que para sser uma cloud-based não é necessário somente a interface gráfica de gerenciamento, é necessário que a controladora possa ser acessada via internet.

### Split MAC architecture

Todas os access points autônomos da estrutura são protegidos por estruturas de split MAC. Cada AP possui suas próprias políticas de segurança como detecção de intrusos, sistemas de prevenção, QoS, gerenciamento de banda, e etc.. qualquer AP pode ser classificada em duas categorias: grupo gerenciamento de funções e grupo funções em tempo real.

- As funções de gerenciamento de AP autônomo incluem gerenciamento de saída de energia de RF, QoS, gerenciamento de segurança, autenticação de cliente e outros programas de gerenciamento. Por outro lado, as funções de tempo real preocupam-se com a transferência de quadros de dados, criptografia e descriptografia de dados e assim por diante.

- O AP automatizado recebe e transfere quadros 802.11 em tempo real. O AP autônomo se comunica com os clientes através da camada física conhecida como camada MAC. O AP autônomo é governado por um administrador centralizado para saída de energia de RF e gerenciamento de segurança.

- O hardware de um AP autônomo é conhecido como ponto de acesso leve porque executa apenas operações em tempo real. O WLC geralmente é responsável pelo gerenciamento do AP autônomo (controlador de LAN sem fio). Os principais itens usados ​​para o desempenho da segurança são a autenticação do usuário e o gerenciamento de políticas de segurança, entre outras coisas. As camadas 1 e 2 são utilizadas para mover quadros dentro do mesmo domínio de RF.

- CAPWAP é uma abreviatura de protocolo de tunelamento de controle e provisionamento de ponto de acesso sem fio, usado para encapsular dados em uma rede sem fio. A conexão CAPWAP é composta por dois túneis distintos, mensagens de controle CAPWAP e dados CAPWAP.

- Mensagens de controle CAPWAP na arquitetura Split MAC:
  - As portadoras de mensagens de controle CAPWAP trocam os códigos necessários para configurar e operar o AP. Somente o WLC associado é capaz de controlar com segurança o AP usando mensagens de controle autenticadas e criptografadas.

- Dados CAPWAP na arquitetura Split MAC:
  - Os dados CAPWAP são usados ​​para transportar pacotes entre clientes sem fio vinculados a um único AP. Os pacotes de dados que trafegam pelo túnel de dados não são criptografados por padrão. Quando a criptografia de dados está habilitada, a segurança da camada de transporte do datagrama é usada para proteger os pacotes (DTLS).
