Spanning tree é um protocolo para prevenir loops de tráfego layer 2 ocasionado pelo Switching Flood. O Protocolo previne loops colocando portas redundantes no `blocking state`, desabilitando a interface.

Essas interfaces funcionam como bakup, que pode entrar no `forwarding state` se uma interface ativa falhar.

Interfaces em `forwarding state` agem normalmente, recebem e transmitem dados tráfego.

Interfaces em `blocking state` apenas enviam e recebem mensagens do STP (BPDU's)

Ao selecionar quais portas estão em `forwarding` e quais estão em `blocking`, o STP cria um caminho único para cada ponto específico da rede. isso previne o loop de layer 2.

Existe uma série de processos definidos que o STP usa para determinar quais portas estarão em `forwarding` e quais estarão em `blocking`.

Switches com STP habilitado enviam e recebem 'Hello' BPDU em todas as interfaces, o padrão do timer de envio é 2s.

Se um switch recebe um 'Hello' BPDU em uma de suas interfaces ele sabe que aquela interface está conectada a outro switch. (Roteadores, PC's, Etc.. não usam o STP)

Switches usam um campo no BPDU para eleger o Bridge Root(switch root) para a rede.

O switch com menor bridge ID se torna o root bridge

TODAS as portas do bridge root são definidas como `forwarding-state` e os outros switches na topologia devem ter um caminho para alcançar o root bridge.

|                        |                     |
| ---------------------- | ------------------- |
| Bridge Priority 16bits | MAC Address 48-bits |

A Bridge priority padrão é 32768 em todos os switches, então por padrão o endereço MAC é o parâmetro usado como desempate na eleição (Menor endereço MAC se torna o root)

Quando o switch liga, ele assume que é o root bridge. Ele desiste da posição após receber o BPDU de um switch com o menor bridge ID.

Assim que a topologia convergir e todos os switches concordarem com o root bridge, apenas o root bridge irá enviar BPDU's.

Outros switches na rede irão enviar esses BPDU's, mas não irão gerar seus próprios BPDU's
### Passos

1. O primeiro passo é eleger o Root Bridge (menor bridge ID / MAC Address)
2. O segundo passo é verificar quais portas dos outros Switches serão Root Ports
3. Após o segundo passo é necessário verificar em CADA domínio de colisão quais interfaces serão Designated com base no root cost de cada rota 
4. Verificar quais portas em cada domínio de colisão estarão bloqueadas

### Rapid STP e Rapid PVST+

RSTP é um algoritmo Spanning-tree baseado na rapidez. O protocolo é um mecanismo de handshake entre switches, o que permite as portas passarem diretamente para o `forwarding state`

Comparação das versões STP
- RSTP estado das portas (discarding, learning, forwarding)
- RSTP função das portas (root, designated, alternate, backup)
- Funções opcionais do STP no RSTP (UplinkFast, BackboneFast,PortFast)
- RSTP BPDU (Enviado por todos os switches, não apenas o switch root)
- Tipos de link RSTP (edge, point-to-point,shared)
