### DHCP
DHCP é usado para permitir que hosts automaticamente/dinamicamente aprendam vários aspectos da configuração da sua rede, como endereços IPs, máscara de rede, gateway, servidor DNS, etc.. 

- Tipicamente usado para clientes.
- Em redes menores normalmente o roteador age como o servidor DHCP para hosts na LAN.
- Em redes maiores o servidor DHCP é normalmente um servidor dedicado.

###### Importância de um Servidor DHCP

- Configuração centralizada: Por centralizar a configuração dos IP's , servidores DHCP permitem que devices clientes aprendam as configuração ao invés de necessitar de configuração manual.
- Mobilidade: Possibilitam com que clientes se conectem á novas redes incluindo redes wireless sem que seja necessária a configuração humana.
- Automação e eficiência: O trabalho manual de administradores de redes é reduzido abaixando também a quantidade de erros humanos na configuração.
- Modelo cliente/server: Benefícios como o gerenciamento centralizado e segurança dos serviços e dados.

Informações providenciadas:
- Endereço IP
- Máscara de subrede 
- Default Gateway
- Endereço do servidor DNS
- Nome de domínio
- Endereço do servidor WINS
- Endereço do servidor TFTP

###### Operação DHCP

DORA
O mecanismo de 4 passos DORA (Discover, Offer, Request, Acknowledgement) é usado no DHCPv4 para comunicação entre servidor e cliente.

Discover: Refere-se á primeira mensagem no processo DORA que ajuda a achar o servidor DHCP na rede. O cliente irá achar o servidor DHCP enviando uma mensagem discover por broadcast na rede. Como o cliente não sabe o endereço IP do servidor DHCP ele enviará a mensagem com destino 255.255.255.255 e o endereço de origem é 0.0.0.0 já que o cliente ainda não possui um endereço IP.
```
Source IP address: 0.0.0.0  
Destination IP address: 255.255.255.255
Source MAC address: MAC address of DHCP clients
Destination MAC address: FF:FF:FF:FF:FF:FF
```


Offer: O servidor DHCP recebe a mensagem discover e responde o cliente com um request Offer DHCP. A mensagem offer possui informações á mais como endereço IP e duração que o host pode usá-lo. O destino do pacote será 255.255.255.255 pois o cliente DHCP ainda não possui IP próprio. a mensagem Offer DHCP será broadcast no layer 3 mas unicast no layer 2.
```
Source IP address: IP Address of DHCP Server
Destination IP address: 255.255.255.255
Source MAC address: MAC address of DHCP Server
Destination MAC address: MAC address of DHCP clients
```

Request: O cliente então envia uma mensagem Request para o servidor após receber uma mensagem Offer do servidor. Essa mensagem diz ao servidor que o cliente aceita o endereço oferecido. O endereço destino será 255.255.255.255 novamente. A razão para isso é que a rede poderia possuir mais de um servidor DHCP então o cliente poderia receber múltiplas mensagens offer e ele aceitará o request que chegar nele primeiro e a mensagem broadcast é pra eliminar outro servidor DHCP. Aqui o endereço de origem será 0.0.0.0 já que o servidor DHCP ainda não atribuiu o endereço IP ao cliente DHCP.
```
Source IP address: 0.0.0.0
Destination IP address: 255.255.255.255
Source MAC address: MAC address of DHCP clients
Destination MAC address: MAC address of DHCP server
```

Acknowledgment: Esse é o último passo ou mensagem no processo DORA. O servidor DHCP envia uma mensagem Acknowledge para o cliente após receber a mensagem Request do cliente. Essa mensagem contém o endereço IP e máscara de sub-rede que o servidor atribui ao cliente. O endereço de origem será o endereço IP do servidor. Essa será novamente uma mensagem broadcast no layer 3 e unicast no layer 2.

### DHCP conflict
Conflitos DHCP refere-se á quando dois ou mais aparelhos recebem o mesmo endereço IP via DHCP. 

##### Causas de conflitos DHCP

- IPs duplicados: Sobreposição de endereços estáticos e dinâmicos (DHCP)
- Servidores DHCP falso: Servidores não autorizados atribuindo endereços IP's
- Configuração de lease: Leases expirados ou duplicados não liberados.
- Configuração errada de devices:
- Sobreposição de pools DHCP:
- Leases expirados sendo reutilizados:
- Múltiplos servidores gerenciando os mesmo endereços

### Práticas anti conflitos DHCP

1. Evitar sobreposição entre endereços estáticos e dinâmicos.
2. Segmentar escopo DHCP por VLAN's, departamentos ou devices.
3. Limpeza e monitoramento dos leases regularmente.
4. Detectar e eliminar servidores DHCP falsos.
5. Uso de ferramentas de monitoramento IPAM e DHCP.

### DNS
DNS é usado para resolver nomes legíveis para humanos em endereços IP's

- Servidores DNS que os aparelhos usam podem ser manualmente configurado ou aprendido via DHCP

### DNS no CISCO IOS
- Para hosts na rede usarem DNS, não é necessário configurar DNS nos roteadores.
  Eles irão simplesmente encaminhar mensagens DNS como qualquer outro pacote.

- De qualquer forma, o roteador Cisco pode ser configurado como um servidor DNS, entretanto é raro.
- O roteador CISCO pode ser configurado como um cliente DNS.
