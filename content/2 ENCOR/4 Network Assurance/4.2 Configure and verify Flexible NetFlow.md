Netflow é um protocolo sistema criado pela CISCO que coleta tráfegos ativos de IP que entram ou saem da interface. Os dados NetFlow são então analisados para diagnosticar o passagem e volume do tráfego.

Possui diversos usos práticos, algumas empresas implementam para conseguir cobrar corretamente um cliente pelo tráfego usado. Pode também ser usado para testar a capacidade de banda de um link para garantir o tráfego.

### Flow

Um **flow** é um fluxo unidirecional de pacotes identificado pela combinação de:

- Endereço IP de origem.
- Endereço IP de destino.
- Porta de origem.
- Porta de destino.
- Protocolo da Camada 3.
- Tipo de Serviço (**ToS**).
- Interface lógica de entrada.

### Arquitetura NetFlow

Os principais componentes necessários para o funcionamento do Netflow são:

- **Flow Exporter** - Dispositivo de rede que observa o tráfego, monta o cache flow e exporta os registros.
- **Flow Collector** - Um servidor que recebe e armazena os registros. Escuta os dados que o **Exporter** envia.
- **Analyzer** - Ferramenta que lê os dados do **Collector** e gera gráficos, relatórios e alertas.

### Versões NetFlow

- **NetFlow v5** — versão clássica, muito usada, mas com campos **fixos**. Só IPv4.
- **NetFlow v9** — introduziu **templates**, permitindo formato flexível e suporte a IPv6, MPLS, etc.
- **Flexible NetFlow (FNF)** — evolução no mundo Cisco, onde **você define** quais campos são chave e quais são coletados, montando seus próprios registros conforme a necessidade. É o modelo moderno.
- **IPFIX** — é o **padrão aberto/IETF** derivado do NetFlow v9.
## Configuração Flexible NetFlow

A configuração do FNF consiste em quatro peças fundamentais de configuração:
1. **Flow Record** - O que coletar
2. **Flow Exporter** - Para onde enviar
3. **Flow Monitor** - Record + Exporter e mantém o cache.
4. **Aplicação na interface** - Onde o monitor é ativado e a direção
---

### Flow Record - O que coletar?

Aqui você usa duas palavras-chave que precisa saber distinguir bem:

- **`match`** — define os campos **chave** (key fields). São eles que **definem o que é um flow** (equivalente às tuplas).
- **`collect`** — define os campos **não-chave**. São dados **acumulados/coletados** sobre o flow, mas que não definem um fluxo novo.

```
flow record RECORD-TESTE
 description Monitora trafego IPv4
 match ipv4 source address
 match ipv4 destination address
 match ipv4 protocol
 match transport source-port
 match transport destination-port
 match ipv4 tos
 collect counter bytes
 collect counter packets
 collect interface input
 collect timestamp sys-uptime first
 collect timestamp sys-uptime last
```

### Flow Record - Para onde enviar?

Define o collector de destino:
```
flow exporter EXPORTER-TESTE
 description Descrição Simples
 destination x.x.x.x
 source GigabitEthernet0/0
 transport udp 9999
 export-protocol netflow-v9
```

### Flow Monitor - Definir Record + Exporter

Monitor é o elemento que amarra **Record + Exporter** e é ele que iremos aplicar na interface no próximo passo:
```
flow monitor MONITOR-TESTE
 description Descrição Simples
 record RECORD-TESTE
 exporter EXPORTER-TESTE
 cache timeout active 60
 cache timeout inactive 15
```

Os **timeouts** controlam quando um flow é exportado:
**`active`** - exporta fluxos de longa duração periodicamente.
**`inactive`** - exporta/remove fluxos que não enviaram novos pacotes.

### Aplicar na interface

Por fim, você ativa o monitor na interface, escolhendo a **direção**:

```
interface GigabitEthernet0/1
 ip flow monitor MONITOR-TESTE input
 ip flow monitor MONITOR-TESTE output
```

- **`input`** — analisa o tráfego que **entra** na interface.
- **`output`** — analisa o que **sai**.

### Verificação

```
show flow record RECORD-TESTE
show flow exporter EXPORTER-TESTE
show flow monitor MONITOR-TESTE
show flow monitor MONITOR-TESTE cache          
show flow monitor MONITOR-TESTE cache format table
show flow interface GigabitEthernet0/1
show flow exporter statistics
```
