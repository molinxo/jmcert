## NETCONF
O **NETCONF (Network Configuration Protocol)** é um protocolo de gerenciamento de dispositivos de rede padronizado pelo **IETF**. Seu objetivo é permitir que aplicações automatizem a configuração de roteadores, switches e outros equipamentos de forma segura, padronizada e confiável.

O protocolo utiliza **RPC (Remote Procedure Call)** para executar operações de gerenciamento e **XML** para representar tanto as mensagens quanto os dados de configuração. A comunicação ocorre sobre um transporte seguro, normalmente **SSH** ou **TLS**
### Arquitetura do NETCONF
O protocolo é dividido em quatro camadas:

- **Content Layer:** contém os dados de configuração e notificações.
- **Operations Layer:** define as operações utilizadas para consultar e modificar configurações.
- **Messages Layer:** encapsula as mensagens RPC, respostas e notificações em XML.
- **Secure Transport Layer:** fornece comunicação segura entre cliente e servidor utilizando SSH ou TLS.

### Modelo de Dados
O conteúdo das mensagens é codificado em **XML**.

Para padronizar a estrutura das configurações, o NETCONF utiliza o **YANG**, uma linguagem de modelagem desenvolvida pelo IETF que descreve:

- Dados de configuração;
- Dados operacionais;
- Notificações;
- Operações RPC.
### Operações Básicas

| Operação          | Função                                                                                |
| ----------------- | ------------------------------------------------------------------------------------- |
| `<get>`           | Obtém a configuração em execução (running) e informações operacionais do dispositivo. |
| `<get-config>`    | Recupera uma configuração específica (running, startup ou candidate).                 |
| `<edit-config>`   | Adiciona, altera, substitui ou remove configurações.                                  |
| `<copy-config>`   | Copia um datastore de configuração para outro.                                        |
| `<delete-config>` | Remove um datastore de configuração.                                                  |
| `<lock>`          | Bloqueia um datastore para impedir alterações simultâneas.                            |
| `<unlock>`        | Libera um datastore previamente bloqueado.                                            |
| `<close-session>` | Encerra a sessão NETCONF normalmente.                                                 |
| `<kill-session>`  | Encerra uma sessão NETCONF de forma forçada.                                          |

### Capacidades (Capabilities)

O NETCONF pode ser estendido por meio de **capabilities**, negociadas entre cliente e servidor durante o estabelecimento da sessão.

Entre as principais capacidades estão:

- **:validate** – valida configurações antes da aplicação.
- **:xpath** – permite consultas utilizando XPath.
- **Notifications** – envio de notificações assíncronas utilizando:
    - `<create-subscription>`
    - `<notification>`
- **Partial Lock** – bloqueio apenas de partes da configuração, permitindo múltiplos administradores trabalharem simultaneamente.
- **Monitoring** – monitora sessões, datastores, estatísticas e permite recuperar modelos YANG através da operação `<get-schema>`.

### Mensagens NETCONF
Todas as mensagens são documentos XML bem formados.

Os principais tipos são:

- **`<rpc>`** – requisição enviada pelo cliente.
- **`<rpc-reply>`** – resposta do servidor.
- **`<notification>`** – notificações assíncronas enviadas pelo servidor.

Cada requisição possui um **message-id**, utilizado para associar a resposta correspondente.

O protocolo também suporta **RPC Pipelining**, permitindo que várias requisições sejam enviadas sem esperar pelas respostas anteriores.

### Transporte Seguro
O NETCONF não define um transporte próprio. Os mais utilizados são:

- **SSH** – método mais comum e amplamente suportado.
- **TLS com autenticação mútua X.509** – utilizado em ambientes que exigem certificados digitais.

## RESTCONF
Protocolo baseado em HTTP que providencia API RESTful e permite que usuários utilizem CRUD e Query de dados dos devices de redes.

O aumento da escala e da complexidade das redes está impulsionando a crescente demanda por automação de operação e manutenção (O&M). O **Network Configuration Protocol (NETCONF)** fornece interfaces de programação de aplicações (APIs) baseadas no mecanismo de **Remote Procedure Call (RPC)**. No entanto, as redes estão evoluindo mais rapidamente do que o NETCONF, tornando necessárias interfaces de programação padronizadas que ofereçam suporte ao acesso por aplicações web e às operações em dispositivos de rede.

O **RESTCONF** foi desenvolvido com base no **NETCONF** e no **HTTP**, fornecendo as principais funcionalidades do NETCONF por meio dos métodos HTTP. Sua interface de programação segue o estilo **RESTful**, amplamente adotado pela indústria de TI, permitindo que os usuários desenvolvam ferramentas de operação e manutenção baseadas na web de forma eficiente.

| **Item**                             | **NETCONF + YANG**                                                                                                                                                                                                                                  | **RESTCONF + YANG**                                                                                                                                                                                                                                                                                                           |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Canal de transmissão (protocolo)** | O NETCONF utiliza preferencialmente o **Secure Shell (SSH)** na camada de transporte e usa o SSH para transmitir informações em **XML**.                                                                                                            | O RESTCONF acessa os recursos dos dispositivos com base no **HTTP**. As interfaces de programação fornecidas pelo RESTCONF seguem o padrão **RESTful**, amplamente adotado pela indústria de TI.                                                                                                                              |
| **Formato dos pacotes**              | Código **XML**                                                                                                                                                                                                                                      | Código **XML** ou **JSON**                                                                                                                                                                                                                                                                                                    |
| **Características das operações**    | As operações do NETCONF são mais complexas. Por exemplo:  <br>• Suporta operações de adição, exclusão, modificação e consulta. <br>• Trabalha com múltiplos bancos de dados (datastores) de configuração.  <br>• Permite rollback de configurações. | As operações do RESTCONF são mais simples. Por exemplo:  <br>• Suporta operações de adição, exclusão, modificação e consulta.  <br>• Suporta apenas o banco de dados de configuração **`<running/>`**.  <br>• As alterações entram em vigor imediatamente, sem necessidade de confirmação em duas fases (_two-phase commit_). |
##### Benefícios:
• Fornece interfaces de programação RESTful para o desenvolvimento de aplicações web.  
• Interfaces padronizadas compatíveis com equipamentos de múltiplos fabricantes, reduzindo custos de desenvolvimento e manutenção.  
• Alta extensibilidade, permitindo que diferentes fabricantes definam operações adicionais ao NETCONF.  
• Não requer uma ferramenta de gerenciamento de rede (**NMS**).
