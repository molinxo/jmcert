# GRE (GENERIC ROUTING ENCAPSULATION)

**GRE** ou **Generic Routing Encapsulation** é um protocolo proprietário CISCO que encapsula pacotes em uma rede de base IP, tornando possível a criação de túneis virtuais entre roteadores por onde os dados são criptografados na saída da rede até chegarem no destino e serem descriptografados pelo outro roteador. O túnel **GRE** permite também o roteamento de protocolos como **RIP, OSPF, EIGRP** entre sites.

### Funcionamento

Quando um roteador utiliza **GRE (Generic Routing Encapsulation)**, ele encapsula o pacote original adicionando um novo cabeçalho IP com o endereço do outro extremo do túnel como destino. Dessa forma, o pacote pode ser roteado entre os dois endpoints do túnel sem analisar seu conteúdo. Ao chegar ao destino, o cabeçalho **GRE** é removido (desencapsulamento), e o pacote original é encaminhado normalmente para a rede de destino.

### Configuração

1. Criar uma interface de túnel GRE.
2. Configurar um endereço IP para a interface do túnel.
3. Definir a origem local do túnel (pode ser uma interface física ou de loopback).
4. Definir o endereço IP de destino remoto do túnel.

- Opcionais
    - Largura de banda (bandwidth) do túnel.
    - Keepalive para monitorar a disponibilidade do túnel.
    - MTU IP da interface do túnel.

```
Site-A#conf t
Site-A(config)#int Tunnel1
Site-A(config-if)#ip address 10.10.10.1 255.255.255.0
Site-A(config-if)#tunnel source 172.16.1.1
Site-A(config-if)#tunnel destination  172.16.2.1
Site-A(config-if)#exit
Site-A(config)#router ospf 1
Site-A(config-router)#router-id 1.1.1.1
Site-A(config-router)#network 10.10.10.0 0.0.0.255 area 0
Site-A(config-router)#network 192.168.1.0 0.0.0.255 area 1
Site-A(config-router)#exit
Site-A(config)#ip route 0.0.0.0 0.0.0.0 172.16.1.2
```

# IPSEC

### IPsec Security Services

IPSec é um conjunto IETF open standards para construir VPN's seguras que usam uma variedade de protocolos e métodos para assegurar os pacotes por redes públicas ou pela Internet

IPSEC oferece os seguintes serviços para segurança do pacote IP:

1. **Peer Authentication –** 
2. **Data Confidentiality –** 
3. **Data Integrity –** 
4. **Replay Detection –** 

Para oferecer serviços de segurança o IPSEC usa as seguintes criptografia, hashing e métodos de chaveamento.

- **Data Encryption Standard (DES)**: a 56-bit symmetric data encryption algorithm used to encrypt data sent over a VPN, not recommended.
- **Triple DES (3DES)**: runs the DES encryption algorithm three times with varying three 56-bit keys, not recommended.
- **Advanced Encryption Standard (AES):** replaces DES and 3DES encryption algorithms, and it supports 128 bits, 192 bits, and 256 bits key lengths. It is based on the Rijndael algorithm.
- **Message Digest 5 (MD5):** a 128-bit hash algorithm used for one-way data authentication. It adds an extra layer of security against MitM attacks. It is not recommended, and SHA should be used instead.
- **Secure Hash Algorithm (SHA):** a 160-bit hash algorithm used for one-way data authentication. It provides an extra layer of security against MitM attacks.
- **Diffie-Hellman (DH):** an asymmetric key exchange protocol that allows peers to generate a shared secret key used by VPN peers for symmetrical algorithms over insecure communication channels. A DH group is the modulus size or key length used for a DH key exchange. The bigger the modulus, the more secure it is.The DH exchange is asymmetrical and CPU intensive, but the generated shared secret keys are symmetrical. Cisco advises not using DH groups 1, 2, and 5 and using DH groups 14 and above instead.
- **RSA Signatures:** a cryptographic mechanism based on public keys or digital certificates utilized to authenticate peers mutually.
- **Pre-Shared Key:** a security method that employs a locally configured key as a credential to authenticate peers mutually.

### IPsec Protocols

IPsec utilizes two packet headers, Authentication Header and Encapsulating Security Payload:

- **Authentication Header (AH)**
	- Fornece **integridade dos dados**, **autenticação** e proteção contra **repetição de pacotes (replay attacks)** por meio de uma assinatura digital (protocolo IP 51). Entretanto, **não oferece criptografia** nem suporta **NAT Traversal (NAT-T)**, por isso seu uso é pouco recomendado e limitado apenas à autenticação.
- **Encapsulating Security Payload (ESP)**
	- Fornece **confidencialidade (criptografia)**, **autenticação** e proteção contra **replay attacks**. Ele criptografa o conteúdo do pacote original (payload), adiciona novos cabeçalhos para a transmissão e utiliza o **protocolo IP 50**. Além disso, é **compatível com NAT Traversal (NAT-T)**, sendo o método mais utilizado no IPsec.

### IPSec Packet Transport Modes

- **Tunnel Mode**
	- O modo túnel encapsula todo o pacote incluindo o header IP, criptografando assim o pacote todo.

- **Transport Mode**
	- O modo de transporte encapsula apenas a carga de dados do pacote dentro do header IP, criptografando assim somente o conteúdo e deixando o header IP de fora da criptografia.

### Transform Sets

- . **Authentication Header Transform**
	- ah-md5-hmac: with MD5 authentication (not recommended)
	- ah-sha-hmac: with SHA authentication
	- ah-sha256-hmac: with 256-bit SHA authentication
	- ah-sha384-hmac: with 384-bit SHA authentication
	- ah-sha512-hmac: with 512-bit SHA authentication

- . **ESP Encryption Transform**
	- esp-aes: with 128-bit AES encryption
	- esp-gcm: with 128-bit (default) or 256-bit authenticated encryption
	- esp-gmac: with 128-bit (default) or 256-bit authentication without encryption
	- esp-aes 192: with 192-bit AES encryption
	- esp-aes 256: with 256-bit AES encryption
	- esp-des: with 168-bit DES encryption (not recommended)
	- esp-3des: with 56-bit DES encryption (not recommended)
	- esp-seal: with 160-bit SEAL encryption
	- esp-null: with null encryption
	
- . **ESP Authentication Transform**
	- esp-md5-hmac: with MD5 authentication (not recommended)
	- esp-sha-hmac: with SHA authentication

- . **IP Compression Transform**
	- comp-lzs: with Lempel-Ziv-Stac (LZS)
