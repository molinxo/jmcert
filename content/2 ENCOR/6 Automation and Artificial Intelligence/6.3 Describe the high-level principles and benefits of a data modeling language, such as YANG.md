Modelos de dados são ferramentas que possibilitam a estruturação dos dados de uma forma que possam ser utilizados para leitura, códigos, automações, etc..

**YANG** é um modelo de dados de base hierárquica que conversa fundamentalmente com as tecnologias NETCONF e RESTCONF. Por este motivo é muito usado em equipamentos CISCO da linha IOS XE.

### Módulos e Sub-módulos

Um **módulo** contém três tipos de declarações:

- **Module-header statements**: descrevem o módulo e fornecem informações sobre ele.
- **Revision statements**: registram o histórico de revisões do módulo.
- **Definition statements**: constituem o corpo do módulo, onde o modelo de dados é definido.

Um módulo pode ser dividido em **submódulos**, de acordo com as necessidades do seu desenvolvedor. Para quem utiliza o módulo, ele continua sendo visto como um único módulo, independentemente da quantidade ou do tamanho dos submódulos.

A instrução **include** permite que um módulo ou submódulo faça referência ao conteúdo existente em submódulos, enquanto a instrução **import** permite referenciar elementos definidos em outros módulos.

### Fundamentos da Modelagem de Dados

O **YANG** define quatro tipos principais de nós para modelagem de dados. Em cada exemplo, é apresentada tanto a sintaxe YANG quanto sua representação equivalente em XML utilizada pelo NETCONF.

#### Leaf Nodes

Um **leaf** contém um dado simples, como um inteiro ou uma string.

Ele possui:

- exatamente um valor;
- um tipo específico;
- nenhum nó filho.

Exemplo:

```
leaf host-name {
    type string;
    description "Hostname for this system";
}
```

Representação XML:

```
<host-name>my.example.com</host-name>
```

Existe também uma variação chamada **leaf vazio (empty)**, utilizada quando apenas a presença do elemento é importante.

Exemplo:

```
leaf enabled {
    type empty;
    description "Enable the interface";
}
```

Representação XML:

```
<enabled/>
```

#### Leaf-list Nodes

Um **leaf-list** representa uma sequência de valores do mesmo tipo.

Exemplo:

```
leaf-list domain-search {
    type string;
    description "List of domain names to search";
}
```

Representação XML:

```
<domain-search>high.example.com</domain-search>
<domain-search>low.example.com</domain-search>
<domain-search>everywhere.example.com</domain-search>
```

#### Container Nodes

Um **container** é utilizado para agrupar nós relacionados em uma mesma árvore de dados.

Ele:

- não possui valor próprio;
- contém apenas nós filhos;
- pode conter leafs, listas, outros containers e leaf-lists.

Exemplo:

```
container system {
    container login {
        leaf message {
            type string;
            description
                "Message given at start of login session";
        }
    }
}
```

Representação XML:

```
<system>
  <login>
    <message>Good morning, Dave</message>
  </login>
</system>
```

#### List Nodes

Uma **list** representa uma sequência de registros.

Cada entrada é identificada de forma única por uma ou mais **chaves (key)**.

Ela pode conter qualquer tipo de nó (leafs, containers, listas etc.).

Exemplo:

```
list user {
    key "name";

    leaf name {
        type string;
    }

    leaf full-name {
        type string;
    }

    leaf class {
        type string;
    }
}
```

Representação XML:

```
<user>
  <name>glocks</name>
  <full-name>Goldie Locks</full-name>
  <class>intruder</class>
</user>

<user>
  <name>snowey</name>
  <full-name>Snow White</full-name>
  <class>free-loader</class>
</user>

<user>
  <name>rzull</name>
  <full-name>Repun Zell</full-name>
  <class>tower</class>
</user>
```

### Dados de Estado (State Data)

Além de modelar **dados de configuração**, o YANG também pode modelar **dados de estado (operacionais)**.

Isso é feito utilizando a instrução:

```
config false;
```

Quando um nó é marcado com **config false**, ele deixa de representar configuração e passa a representar informações operacionais do dispositivo.

Esses dados podem ser consultados com:

- **NETCONF `<get>`** → retorna dados operacionais.
- **NETCONF `<get-config>`** → retorna apenas dados de configuração.

#### Exemplo

Uma interface possui:

- velocidade configurada (**speed**)
- velocidade realmente detectada (**observed-speed**)

```
leaf observed-speed {
    type uint32;
    config false;
}
```

A velocidade observada pode ser consultada, mas **não pode ser alterada** pelo NETCONF.

### Tipos de Dados Nativos (Built-in Types)

O YANG possui diversos tipos de dados internos semelhantes aos de linguagens de programação.

Principais tipos:

| Tipo                       | Descrição                       |
| -------------------------- | ------------------------------- |
| binary                     | Dados binários                  |
| bits                       | Conjunto de bits (flags)        |
| boolean                    | true ou false                   |
| decimal64                  | Número decimal                  |
| empty                      | Valor vazio                     |
| enumeration                | Enumeração                      |
| identityref                | Referência para identidade      |
| instance-identifier        | Referência para um nó da árvore |
| int8/int16/int32/int64     | Inteiros com sinal              |
| uint8/uint16/uint32/uint64 | Inteiros sem sinal              |
| leafref                    | Referência para outro leaf      |
| string                     | Texto                           |
| union                      | Permite vários tipos diferentes |


### Tipos Derivados (typedef)

O comando **typedef** permite criar novos tipos a partir de tipos existentes.

Exemplo:

```
typedef percent {
    type uint16 {
        range "0 .. 100";
    }

    description "Percentage";
}
```

Depois disso o novo tipo pode ser reutilizado:

```
leaf completed {
    type percent;
}
```

Também é possível restringir diretamente um tipo sem criar um typedef.

### Agrupamentos (grouping)

O comando **grouping** cria grupos reutilizáveis de nós.

Isso evita repetição de código.

Exemplo:

```
grouping target {
    leaf address {
        type inet:ip-address;
    }

    leaf port {
        type inet:port-number;
    }
}
```

Depois o grupo pode ser reutilizado:

```
uses target;
```

### Refinamento (refine)

Quando um grouping é reutilizado, algumas propriedades podem ser modificadas através do comando:

```
refine
```

Isso permite alterar, por exemplo:

- descrição
- obrigatoriedade
- comportamento

sem modificar o grouping original.

### Choice e Case

O YANG permite criar escolhas mutuamente exclusivas.

Isso é feito através de:

```
choice
case
```

Cada **case** representa um conjunto de nós.

Quando um case é escolhido, todos os outros tornam-se inválidos automaticamente.

Exemplo:

```
choice snack {

   case sports-arena {
      pretzel
      beer
   }

   case late-night {
      chocolate
   }

}
```

Nesse exemplo o dispositivo aceita apenas **uma das opções**.

### Augment

O comando **augment** permite adicionar novos elementos a um modelo YANG já existente.

É muito utilizado por fabricantes para adicionar funcionalidades proprietárias a modelos padronizados.

Exemplo:

Adicionar um campo **uid** ao modelo de usuários.

```
augment /system/login/user {
    leaf uid {
        type uint16;
    }
}
```

O novo campo passa a aparecer normalmente no XML.

### Definição de RPC

O YANG também permite definir operações RPC utilizadas pelo NETCONF.

Cada RPC possui:

- entrada (**input**)
- saída (**output**)

Exemplo:

```
rpc activate-software-image {

    input {
        leaf image-name
    }

    output {
        leaf status
    }

}
```

O cliente envia uma requisição RPC.

O dispositivo responde com um **rpc-reply**.

### Definição de Notificações

O YANG permite definir notificações que poderão ser enviadas automaticamente pelo NETCONF.

Exemplo:

```
notification link-failure {

    leaf if-name

    leaf if-admin-status

}
```

Quando ocorre uma falha de link, o dispositivo envia uma notificação contendo:

- interface afetada;
- estado administrativo;
- horário do evento.
