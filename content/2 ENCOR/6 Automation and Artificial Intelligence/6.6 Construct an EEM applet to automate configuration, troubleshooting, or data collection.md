O **EEM (Embedded Event Manager)** é um componente de software da Cisco que permite aos administradores de rede automatizar diversas tarefas. O EEM funciona de forma semelhante a uma linguagem de programação baseada na lógica **"se {condição} então {ação}"**. Quando uma condição é atendida, uma ou mais ações são executadas automaticamente no dispositivo.

Um EEM é composto por dois elementos principais:

- **Evento (Event):** define qual evento será monitorado.
- **Ação (Action):** define o que será executado quando o evento ocorrer.

Existem três etapas para criar um **EEM Applet**:

1. Criar o applet e atribuir um nome com o comando:

```
event manager applet <nome-do-applet>
```

2. (Opcional) Definir qual evento será monitorado, normalmente utilizando o comando:

```
event cli pattern
```

3. Definir as ações que serão executadas quando o evento ocorrer, geralmente utilizando os comandos **action** ou **set**.

### Observações

- Os comandos **event** especificam os critérios que disparam o applet.
- Os comandos **action** definem as ações executadas quando o evento ocorre.
- O comando **set** é utilizado para definir valores de variáveis do EEM.

É mais fácil compreender o funcionamento do EEM através de exemplos.

> **Nota:** Os exemplos foram testados no Cisco IOS **15.4(1)T**. Algumas palavras-chave podem não estar disponíveis em versões mais antigas.

# Exemplo 1

### Exibir uma mensagem de boas-vindas com o comando `show my welcome`

Por padrão, esse comando não existe no Cisco IOS e retorna erro. Com o EEM podemos interceptar esse comando e exibir uma mensagem personalizada.

### Configuração

```
event manager applet SHOW-MY-WELCOME-COMMAND
 event cli pattern "show my welcome" enter
 action 1 puts "Hello!!! Welcome to digitaltut.com!!!"
```

### Explicação

- `event manager applet SHOW-MY-WELCOME-COMMAND` cria um applet chamado **SHOW-MY-WELCOME-COMMAND**.
- `event cli pattern` monitora os comandos digitados no terminal (VTY). Quando o comando **show my welcome** é detectado, o evento é acionado.
- A palavra-chave **enter** indica que o evento ocorre quando a tecla **Enter** é pressionada.
- A ação **puts** escreve uma mensagem no terminal ativo.

### Observações

O comando será reconhecido em qualquer modo de configuração (EXEC, configuração global, VTY, etc.).

Para restringi-lo apenas ao modo EXEC:

```
event cli pattern "show my welcome" mode exec enter
```

Outro detalhe é que qualquer comando contendo o texto **show my welcome** também será aceito. Por exemplo:

```
KKSKSshow my welcomeFDFK
```

Para exigir correspondência exata, utiliza-se **Expressão Regular**:

```
event cli pattern "^show my welcome$" mode exec enter
```

Onde:

- `^` = início da string.
- `$` = fim da string.

Essa é a forma recomendada.

### Verificação

```
show event manager policy registered
```

# Exemplo 2

### Executar um EEM manualmente

Neste exemplo, o applet apenas envia uma mensagem ao Syslog quando executado manualmente.

### Configuração

```
event manager applet Welcome_to_digitaltut
 event none
 action 1 syslog msg "Welcome to digitaltut!!!"
```

### Explicação

- `event none` impede a execução automática do script.
- O applet só é executado através do comando:

```
event manager run Welcome_to_digitaltut
```

- `syslog msg` envia uma mensagem para o Syslog.

### Saída

```
Router# event manager run Welcome_to_digitaltut

*Apr 27 07:26:39.551:
%HA_EM-6-LOG: Welcome_to_digitaltut:
Welcome to digitaltut!!!
```

# Exemplo 3

### Bloquear o comando `show processes`

Também será enviado um Syslog com prioridade **Critical**.

### Configuração

```
event manager applet BLOCK-SHOW-PROCESSES-COMMAND
 event cli pattern "show proc" sync yes
 action 1 syslog priority critical msg "Syslog message: show processes command entered"
 action 2 puts "This command is blocked!"
 action 3 set _exit_status "0"
```

### Explicação

- O padrão **show proc** captura comandos como:

```
show process
show processes
do show processes
```

- Não é recomendado usar **show pro**, pois bloquearia também:

```
show protocols
```

- A opção **sync yes** faz o EEM executar antes do comando CLI, permitindo bloqueá-lo.
- `syslog priority critical` define a prioridade da mensagem.
- Definir:

```
set _exit_status "0"
```

bloqueia a execução do comando original.

Se fosse:

```
set _exit_status "1"
```

o comando seria executado normalmente.

É possível inserir novas ações utilizando numeração decimal:

```
action 2.1
action 2.2
```

# Exemplo 4

### Criar um comando simplificado para executar `clear counters`

O objetivo é ocultar automaticamente a confirmação (`[confirm]`).

### Configuração

```
event manager applet CLEAR-COUNTERS
 event none
 action 1 cli command "enable"
 action 2 cli command "clear counters" pattern "\[confirm\]"
 action 3 cli command "y"

alias exec cc event manager run CLEAR-COUNTERS
```

Agora basta executar:

```
cc
```

### Explicação

- `cli command` executa comandos via CLI.
- Como `[` e `]` possuem significado especial em expressões regulares, devem ser escapados:

```
\[
\]
```

- O comando **alias** cria um atalho para executar o applet.

# Exemplo 5

### Integrando EEM com IP SLA

Neste exemplo, o EEM monitora um **IP SLA** e gera um alerta caso o vizinho fique inacessível.

### Configuração do IP SLA (R1)

```
ip sla 10
 icmp-echo 192.168.1.2
 timeout 5000
 frequency 10

ip sla schedule 10 life forever start-time now

track 10 ip sla 10 reachability
```

### Configuração do EEM

```
event manager applet EEM_IP_SLA
 event track 10 state down
 action 1 syslog msg "Syslog: IP SLA 10 is down"
 action 2 puts "IP SLA 10 is down!"
```

Quando a interface do roteador vizinho é desligada, o EEM detecta a perda de conectividade e:

- envia uma mensagem ao Syslog;
- exibe uma mensagem no terminal.

# Resumo

Os principais **detectores de eventos (Event Detectors)** do EEM incluem:

- Monitoramento de objetos SNMP.
- Monitoramento de mensagens Syslog (com suporte a Expressões Regulares).
- Monitoramento de contadores de interfaces.
- Interceptação de comandos CLI.
- Execução manual (`event none`).
- Temporizadores (Countdown, Watchdog e CRON).
- Eventos de IP SLA e NetFlow.

As principais **ações** que o EEM pode executar são:

- Enviar e-mails.
- Executar comandos Cisco IOS.
- Gerar traps SNMP.
- Reiniciar o equipamento.
- Gerar mensagens Syslog com diferentes prioridades.
- Alternar para um processador secundário em plataformas redundantes.
- Coletar informações do sistema automaticamente (como `show tech` ou `show processes cpu history`) quando um evento ocorre.
