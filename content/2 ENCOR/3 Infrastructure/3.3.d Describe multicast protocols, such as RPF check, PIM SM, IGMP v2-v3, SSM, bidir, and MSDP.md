Multicast em redes de computadores refere-se ao método de transmissão de dados na qual o enviador envia uma única cópia do pacote para um grupo de receptores. Essa tecnologia otimiza a rede em vários aspectos que serão abordados neste tópico.

O modelo de Multicast soluciona alguns problemas, como a necessidade de um servidor enviar o mesmo pacote para diferentes destinos sobrecarregando a máquina.. Otimiza a banda da rede e o gasto de recursos dos devices da rede..
### Funcionamento do Multicast
1. Um enviador transmite uma única cópia do pacote
2. Receptores se conectam ao grupo multicast. A rede então identifica os membros do grupo.
3. Dados são replicados apenas quando necessário e enviados aos receptores de destino.
4. Devices que não são membros do grupo não recebem a transmissão.

### Tipos de Multicast

**IP Multicasting** - Multicast configurado via IP

**Application Multicast** - Multicast configurado via Aplicacao

**Source-Specific Multicasting (SSM)** - Método de entrega de pacotes Multicast onde pacotes são entregues apenas á receptores originados por um endereco source especifico definido pelo receptor.

**Any-Source Multicasting (ASM)** - Método de multicast em que **múltiplas fontes** podem enviar tráfego para o mesmo grupo multicast, e os receptores recebem dados de todas as fontes. A rede Multicast deve:
1. discover all multicast sources sending to that address, and
2. route data from all sources to all interested receivers.

### RPF Check
Reverse-Path Check é usado junto com o protocolo de roteamento Multicast como o MSDP ou PIM pra prevenir loops de pacotes Multicast. 

O roteador recebe um pacote multicast, consulta sua tabela de roteamento e verifica se o pacote chegou pela interface que seria utilizada para alcancar a origem do pacote. Caso a interface esteja correta o RPF Check encaminha o pacote. Caso contrário o RPF Check falha e o pacote é descartado.

**Requisitos**
- A tabela de roteamento unicast deve estar correta.
- O caminho entre origem e destino deve ser **simétrico**.
### PIM (Protocol Independent Multicast)
Refere-se á uma família de protocolos Multicast construídos por cima do protocolo IP que oferecerem distribuicao de dados one-to-many e many-to-many entre devices. 

PIM não oferece seu próprio protocolo de descobrimento de rede, ao invés disso usa o informacoes de rota recebidas de outros protocolos de roteamento. Usa a tabela de Roteamento Unicast para fazer o RPF (Reverse-Path Forwarding).

**PIM Sparse Mode (PIM-SM)**
- Utiliza um Rendezvous Point (RP) para construir a árvore multicast.
- Pode migrar para a Shortest Path Tree (SPT) para otimizar o caminho.
- Escalável e o modo mais utilizado em redes corporativas e WANs.
**PIM Dense Mode (PIM-DM)**
- Envia inicialmente o tráfego multicast para toda a rede (Flood).
- Roteadores sem receptores enviam mensagens de Prune para interromper o tráfego.
- Simples de configurar, porém pouco escalável.
**Bidirectional PIM (Bidir-PIM)**
- Utiliza uma árvore compartilhada bidirecional.
- Não cria Shortest Path Tree (SPT).
- Escalável para muitos receptores e fontes, porém pode aumentar a latência.
**PIM Source-Specific Multicast (PIM-SSM)**
- Cada grupo multicast está associado a uma única fonte.
- Os receptores ingressam diretamente no canal (S,G).
- Mais seguro, eficiente e escalável.
- Muito utilizado para streaming e distribuição de vídeo.

### IGMP (Internet Group Management Protocol)

O **IGMP** é um protocolo utilizado em **IPv4** para gerenciar a participação de hosts em **grupos multicast**. Ele permite que os dispositivos informem ao roteador se desejam **entrar** ou **sair** de um grupo multicast.

### MSDP (Multicast Source Discovery Protocol)
É um protocolo da pilha PIM que interconecta múltiplos domínios PIM-SM utilizando de um RP (Rendezvous Point) que oferece redundância e multicasting inter-domínios.

MSDP usa TCP como protocolo de transporte, cada árvore multicast necessita ter o seu próprio RP. Todos os RP são peers entre eles. Mensagens possuem um endereco source e um endereco de grupo multicast .

Se o domínio de RP receber um pacote ele determina se há receptores no grupo. Quando isso acontece, é enviado um PIM Join para o domínio onde está a fonte do multicast, permitindo que o tráfego seja recebido. Em uma sessão de peering, um dos vizinhos MSDP permanece aguardando novas conexões TCP na porta 639.
