#### Classification
Primeiro passo de qualquer trabalho relacionado á QoS é a inspeção profunda do tráfego. Refere-se a ação de classificar o trafego em categorias de trafego que possuem características similares

Classificação QoS usa descritores de trafego como critério e incluem alguns como:

- Internal – QoS group
- Layer 1 – Physical interface
- Layer 2 – 802.1Q/p Class of Service (CoS) bits and MAC addresses
- Layer 2.5 – MPLS Experimental (EXP) bits
- Layer 3 – Differentiated Services Code Point (DSCP) value, IP Precedence value (IPP), and source and destination IP addresses
- Layer 4 – TCP and UDP ports
- Layer 7 – Next Generation Network-Based Application Recognition (NBAR2)

**NBAR2** é uma ferramenta de inspeção profunda dos pacotes usado para classificar e reconhecer um vasto range de protocolos e aplicações utilizando dados do layer 3 ao layer 7, incluindo aplicações que acessam números de portas TCP e UDP.


**NBAR2** possui dois modos de operação que são:

- Protocol Discovery – Identifica e obtêm estatísticas em tempo real de aplica coes que estão operando na rede. Essas estatísticas podem especificar classes e policies usando configuração MQC.
- Modular QoS CLI (MQC) – Tráfegos de rede que correspondem á um protocolo específico podem ser classificados em diferentes classes. Diferentes policies podem ser aplicadas nessas classes após a classificação.

#### Marking
Após a classificação dos headers IP baseados no seu conteúdo, é feita a marcação QoS que inclui alguns bits em posições especificas do header de rede. possibilitando que as ferramentas QoS de outros dispositivos possam classificar o tráfego baseado em valores marcados.

Marcações podem ser feitas em diferentes níveis como o header layer 2, label MPLS, header pacote IP, NBAR, deep packet inspection, etc..

Em outras tecnologias WAN, é possível usar um bit único no Frame Relay e redes ATM para marcar o frame no QoS Layer 2. Frame Relay determina o bit DE (elegibilidade de descarte) e o ATM define o bit CLP (cell loss priority).

O DSCP é a principal ferramenta QoS porque o roteador rapidamente verifica o bit único no header IP. O DSCP não altera o endereço IP de origem ou destino.

**QoS Trust Boundary**

É a ideia usada para não possibilitar manipulacao da prioridade de tráfego de end devices. Após a inclusao de um equipamento de rede na trust boundary nao há necessidade de remarcar nenhum pacote.
#### Queuing
Filas são buffers nos equipamentos de rede que são usados para armazenar pacotes baseados em classes, quando a interface se ocupa ou quando a banda é totalmente utilizada. Alguns tráfegos podem ser processado antes ou depois quando a interface estiver disponível novamente.

Alguns tipos de tráfego podem ser classificados como delay-sensitive, como voz ou video, baixa prioridade ou dados best-effort. normalmente um máximo de oito filas são possível na porta de um device.

Quanto mais alta é a prioridade da fila sempre é para o tráfego importante como controle de redes, tráfego de roteamento seguido por voz e vídeo. Outros tráfegos como web-browsing ou email podem ser achados em filas de prioridade mais baixa.

###### CISCO QoS Queues
Filas são configuradas em aparelhos de rede de diferentes formas. Abaixo estão as duas principais formas nos devices CISCO:

**Priority Queues (PQs)** – Usado para pacotes que precisam de baixa latência e baixa variacao de processo. Durante periodos de congestionamento, PQs irão dropar novos pacotes.

**Class-Based Weighted Fair Queuing (CBWFQ)** – Usado para tráfego não sensível. Durante congestionamento, cada fila consegue especificar banda reservada que garante acessibilidade para uma classe específica. Possibilita a configuração de burst de tráfego.

#### Congestion Management 
Gerenciamento de congestionamento otimiza o fluxo da rede diminuindo gargalos para que a ocupação das portas não interrompa o tráfego.
###### Causas Congestionamento
- **Baixa banda**
- **Design de rede ruim** 
- **Hardware legado** 
- **Muitos equipamentos no broadcast** 
- **Broadcast storms** 
- **Utilizacao de CPU** 
###### Congestion Avoidance
- **Tail Drop** - Método padrão. Trata todos os tráfegos igualmente. Durante momentos de tráfego pesado filas se formam. Quando a fila está cheia pacotes novos são dropados.
- **RED e WRED** - São dois mecanismos de configurar as filas. RED descarta pacotes novos na fila de forma aleatória e WRED coloca pesos diferentes para a prioridade do tráfego para descartá-los.

#### Policing
Controla o nível que pacotes entram na rede para garantir que os recursos da rede serão alocados corretamente. Policing é comumente configurado nas interfaces de saída da rede para limitar o tráfego entrando e saindo da rede.

Muitas configuracoes de policing enviam tráfego quando está dentro do rate e dropam os pacotes quando esse rate é alcancado ou pode ser enviado á outra fila com prioridade diferente.

As seguintes funcoes são feitas por configuracoes de policing:
- Restringir uma classe de tráfego na entrada ou saída baseado em critério.
- Redefinir os bits CLP,DE,DSCP e QoS para marcar pacotes

#### Shaping
Gerencia o fluxo de tráfego, fazendo com que a interface precise dar match em diversas policies. Tráfego que seguir um perfil específico poderá ser encaminhado de forma diferente. Aplicando o máximo de tráfego possível para uma interface o shaping regula e otimiza o fluxo.

Esta estratégia é comparada com o policing do tráfego mas aqui os pacotes são guardados no buffer para serem enviados e não descartados.
